🔐 1. Authentification et Connexion

L'utilisateur fournit ses identifiants. Le backend valide les informations en base de données et génère un JWT token pour les futures requêtes.
sequenceDiagram actor User participant Frontend participant Backend participant Database User->>Frontend: Saisir identifiants Frontend->>Backend: POST /api/auth/login Backend->>Database: Chercher utilisateur Database-->>Backend: Utilisateur trouvé Backend-->>Frontend: JWT Token Frontend->>Frontend: Stocker token Frontend-->>User: Redirection Dashboard

📍 Endpoints:

  • POST /api/auth/login
  • GET /api/user/profile

📋 2. Gestion des Congés

L'employé demande un congé. Le responsable reçoit une notification et peut l'approuver ou le rejeter.
sequenceDiagram actor Employee actor Manager participant Frontend participant Backend participant Database Employee->>Frontend: Cliquer Demander congé Frontend->>Backend: POST /api/leave/request Backend->>Database: Créer demande Database-->>Backend: Confirmé Backend-->>Employee: Confirmation Note over Backend: Notifier le responsable Manager->>Frontend: Accéder Approbations Frontend->>Backend: GET /api/leave/pending Backend->>Database: Récupérer demandes Database-->>Backend: Demandes Backend-->>Frontend: Afficher demandes Manager->>Frontend: Approuver Frontend->>Backend: PUT /api/leave/{id}/approve Backend->>Database: Mettre à jour statut Database-->>Backend: Confirmé Backend-->>Employee: Notification approuvé

📍 Endpoints:

  • POST /api/leave/request
  • GET /api/leave/pending
  • PUT /api/leave/{id}/approve

👤 3. Pointage par Reconnaissance Faciale

L'employé se présente devant le kiosk. La reconnaissance faciale valide l'identité et enregistre le pointage.
sequenceDiagram actor Employee participant Kiosk participant FaceAPI participant Backend participant Database Employee->>Kiosk: Se présenter caméra Kiosk->>Kiosk: Capturer visage Kiosk->>FaceAPI: POST /recognize FaceAPI-->>Kiosk: ID + confiance Kiosk->>Backend: POST /api/attendance/checkin Backend->>Database: Créer enregistrement Database-->>Backend: Confirmé alt Retard détecté Backend->>Kiosk: Alerte Retard Kiosk-->>Employee: Affichage alerte else Normal Backend->>Kiosk: OK validé end Kiosk-->>Employee: Pointage enregistré

📍 Endpoints:

  • POST /api/attendance/checkin
  • GET /api/attendance/records

💰 4. Génération de la Paie

Le responsable RH génère les bulletins de paie. Le système calcule automatiquement les montants et génère les PDF.
sequenceDiagram actor RH participant Frontend participant Backend participant PayrollEngine participant Database RH->>Frontend: Accéder Gestion Paie Frontend->>Backend: GET /api/payroll/config Backend->>Database: Récupérer config Database-->>Backend: Config Backend-->>Frontend: Afficher formulaire RH->>Frontend: Sélectionner mois année Frontend->>Backend: POST /api/payroll/generate Backend->>Database: Récupérer employés Database-->>Backend: Liste employés Backend->>PayrollEngine: Calculer bulletins PayrollEngine-->>Backend: Bulletins calculés Backend->>Database: Stocker bulletins Database-->>Backend: Confirmé Backend-->>Frontend: Bulletins générés RH->>Frontend: Valider paie Frontend->>Backend: PUT /api/payroll/validate Backend->>Database: Mettre à jour soldes Database-->>Backend: Confirmé Backend-->>RH: Paie validée

📍 Endpoints:

  • GET /api/payroll/config
  • POST /api/payroll/generate
  • PUT /api/payroll/validate

👨‍💼 5. Gestion du Recrutement

Les candidats consultent les offres et soumettent leur candidature. Le responsable RH peut approuver ou rejeter les candidatures.
sequenceDiagram actor Candidate actor RH participant Website participant Backend participant Database participant Email Candidate->>Website: Accéder offres Website->>Backend: GET /api/jobs/open Backend->>Database: Récupérer offres Database-->>Backend: Offres Backend-->>Website: Afficher offres Candidate->>Website: Postuler Website->>Website: Remplir CV LM Website->>Backend: POST /api/applications Backend->>Database: Créer candidature Database-->>Backend: Confirmé Backend->>Email: Envoyer confirmation Email-->>Candidate: Email reçu Note over Backend: Notifier le RH RH->>Website: Accéder candidatures Website->>Backend: GET /api/applications Backend->>Database: Récupérer candidatures Database-->>Backend: Candidatures Backend-->>Website: Afficher candidatures RH->>Website: Planifier entretien Website->>Backend: PUT /api/applications/{id} Backend->>Email: Envoyer invitation Email-->>Candidate: Invitation entretien Backend-->>RH: Candidat contacté

📍 Endpoints:

  • GET /api/jobs/open
  • POST /api/applications
  • GET /api/applications
  • PUT /api/applications/{id}

📱 6. Dashboard Employé

L'employé accède au dashboard avec ses données. Les notifications temps réel s'affichent via WebSocket.
sequenceDiagram actor Employee participant Frontend participant Backend participant Database participant Cache as Redis Cache participant WebSocket Employee->>Frontend: Se connecter Frontend->>Backend: POST /api/auth/login Backend-->>Frontend: JWT Token Frontend->>Backend: GET /api/dashboard Backend->>Cache: Chercher en cache alt Cache hit Cache-->>Backend: Données else Cache miss Backend->>Database: Récupérer données Database-->>Backend: Données Backend->>Cache: Stocker en cache end Backend-->>Frontend: Données profil Frontend->>Frontend: Afficher Dashboard par Charger données Frontend->>Backend: GET /api/my-leaves Backend->>Database: Congés Database-->>Backend: Congés Backend-->>Frontend: Congés and Charger paie Frontend->>Backend: GET /api/my-payslips Backend->>Cache: Paies Cache-->>Backend: Paies Backend-->>Frontend: Paies and Charger présence Frontend->>Backend: GET /api/my-attendance Backend->>Database: Présence Database-->>Backend: Présence Backend-->>Frontend: Présence end Frontend->>WebSocket: Connexion WebSocket Note over WebSocket: Notifications temps réel Backend->>WebSocket: Nouveau bulletin WebSocket-->>Frontend: Notification Frontend->>Frontend: Afficher notification

📍 Endpoints:

  • GET /api/dashboard
  • GET /api/my-leaves
  • GET /api/my-payslips
  • GET /api/my-attendance

⚡ WebSocket/STOMP Notifications temps réel

⭐ 7. Gestion des Évaluations

Le responsable remplit les évaluations de ses employés. L'employé reçoit une notification et peut consulter ses résultats.
sequenceDiagram actor Manager actor Employee participant Frontend participant Backend participant Database participant Email Manager->>Frontend: Accéder Évaluations Frontend->>Backend: GET /api/evaluations/pending Backend->>Database: Équipe à évaluer Database-->>Backend: Équipe Backend-->>Frontend: Afficher employés Manager->>Frontend: Commencer évaluation Frontend->>Backend: GET /api/evaluations/template Backend->>Database: Récupérer formulaire Database-->>Backend: Questions Backend-->>Frontend: Afficher formulaire Manager->>Frontend: Remplir scores commentaires Frontend->>Backend: POST /api/evaluations Backend->>Database: Créer évaluation DRAFT Database-->>Backend: Confirmé Manager->>Frontend: Soumettre Frontend->>Backend: PUT /api/evaluations/{id} Backend->>Database: MAJ statut SUBMITTED Database-->>Backend: Confirmé Backend->>Email: Envoyer notification Email-->>Employee: Email évaluation Note over Backend: Notification WebSocket Employee->>Frontend: Consulter évaluation Frontend->>Backend: GET /api/evaluations/{id} Backend->>Database: Récupérer évaluation Database-->>Backend: Résultats Backend-->>Frontend: Afficher résultats

📍 Endpoints:

  • GET /api/evaluations/pending
  • GET /api/evaluations/template
  • POST /api/evaluations
  • PUT /api/evaluations/{id}
